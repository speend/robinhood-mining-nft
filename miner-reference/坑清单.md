# 坑清单（按重要性排序）

## 1. 字节序坑（最致命）⚠️

**症状**：矿机看起来一切正常（有算力、有进度条、能挖出"码"），但合约永远拒绝——`isValidNonce` 返回 false。

**原因**：keccak 状态按 lane（8 字节）组织，lane 内部是小端装载；而合约的消息是"地址 + 大端 nonce"，校验还要求结果按大端比较。不做 `bswap32` 就全错。

**自检方法**：随便挖一个码，喂给合约的 `isValidNonce(地址, nonce, bits)`。
- 返回 `true` → 格式对了
- 返回 `false` → 100% 是字节序问题

**别自己重推**：直接用 `keccak_miner.wgsl` 里验证过的实现。

## 2. 性能坑（45 倍差距）

同样的算法，实现质量决定速度：

| 实现 | 算力 |
|------|------|
| 浏览器 JS 单线程 | ~2 MH/s |
| 多线程 Worker | ~20 MH/s |
| **本包 WebGPU shader（RTX 4060 实测）** | **630 ~ 900 MH/s** |

**注意**：算力必须按 `已尝试次数 ÷ 耗时` 实测，不能看理论值。优化方向：workgroup 大小（当前 64）、每线程迭代次数（当前 256）、减少寄存器压力。集成显卡会慢 10~50 倍，页面应标注"建议独立显卡"。

---

## 3. 难度会中途变化

玩家挖的过程中，一旦有人 mint 成功，档位可能上涨 → 难度 +1 bit → **手里的码当场作废**。

**处理**：每隔一段时间（比如每 30 秒）重读 `currentBits()`，发现变了立刻换目标，别把过期码提交上去浪费 gas。

## 4. 价格会中途跳档

同理，提交前必须**重读** `currentMintDue()`，按最新价格付 ETH。多一分少一分合约都会 revert（`WrongPayment`）。

## 5. nonce 不能重复

同一地址的同一 nonce 只能用一次。连续挖多张时，把上次成功的 nonce 记下来（存 localStorage），从之后继续，避免白挖。

## 6. 浏览器的坑

- 标签页切到后台可能被降频/暂停 → 提示用户保持页面前台
- 笔记本合盖/休眠会中断 → 需要"断点续挖"（nonce 搜索是无状态的，关掉页面重开接着挖就行，不丢进度）
- WebGPU 需要较新 Chrome / Edge；不支持时要给出明确提示，别让用户对着黑屏发呆

## 7. 提交后的连锁处理

- 交易发出后**等确认**再开始下一轮挖矿
- 记录已提交的 nonce，防止页面刷新后重复提交
- 交易失败（价格跳档等）要能自动重试：重读难度和价格 → 重挖/重提交
