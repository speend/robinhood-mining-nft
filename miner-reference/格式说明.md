# 合约验证规则（矿机必须完全匹配）

## 一句话

矿机的任务：找一个 **nonce**，使 `keccak256(地址 ‖ nonce)` 的结果**高 N 位为 0**（N = 当前难度 bits）。

## 精确格式

```
消息 = abi.encodePacked(address(20字节), uint64 nonce)   → 共 28 字节

字节布局：
  b0 .. b19    玩家钱包地址（20 字节）
  b20 .. b27   nonce，uint64，大端排列（8 字节）
  b28          0x01（keccak 填充 —— 注意不是 SHA3 的 0x06）
  b135         0x80（结束标记）

校验 = keccak256(消息) 的 32 字节结果，按【大端】当作 256 位整数，高 bits 位全 0 即达标
```

合约里的等价代码（`contracts/src/Mine.sol`）：

```solidity
keccak256(abi.encodePacked(user, nonce))  →  uint256(hash) >> (256 - bits) == 0
```

## 难度和价格从哪读

```solidity
Mine.currentBits()      // 当前难度（bits）
Mine.currentMintDue()   // 当前价格（wei）—— mint 时 msg.value 必须精确等于它
Mine.isValidNonce(地址, nonce, bits)  // 免费校验一个码是否合法
Mine.minted()           // 已铸造数量（= 已卖张数）
```

难度公式：`currentBits = baseBits + (minted / 500) * bitsPerTier`，上线配置：**35 起，每档 +1，不封顶**。

## 字节序（最大的坑，见坑清单第 1 条）

keccak 状态按 lane 组织，每 lane 覆盖 8 字节，lane 的 lo/hi 两个 u32 都是**小端**装载。
→ 写入地址和 nonce 前要 `bswap32`；读结果比较前也要 `bswap32`。参考 `keccak_miner.wgsl` 里的现成实现，别自己重推。

## 提交前必须做的本地校验

```js
// 用合约免费校验，通过了再花 gas
const ok = await client.readContract({
  address: MINE, abi: mineAbi,
  functionName: 'isValidNonce', args: [account, nonce, bits],
});
if (!ok) return; // 码无效（多半是字节序错了，或难度涨了）
```

## 前端集成示例（viem）

```js
import { createPublicClient, createWalletClient, custom, parseAbi, http } from 'viem';

const mineAbi = parseAbi([
  'function currentBits() view returns (uint256)',
  'function currentMintDue() view returns (uint256)',
  'function isValidNonce(address user, uint64 nonce, uint256 bits) view returns (bool)',
  'function mint(uint64 nonce) payable',
]);

// 1) 读难度和价格
const bits = await publicClient.readContract({ address: MINE, abi: mineAbi, functionName: 'currentBits' });
const due  = await publicClient.readContract({ address: MINE, abi: mineAbi, functionName: 'currentMintDue' });

// 2) GPU 挖出 nonce（参考 grinder.html + keccak_miner.wgsl）

// 3) 免费校验
const ok = await publicClient.readContract({
  address: MINE, abi: mineAbi, functionName: 'isValidNonce', args: [account, nonce, bits],
});
if (!ok) { /* 重新挖 */ }

// 4) 提交（value 必须是重读后的最新价格）
const dueNow = await publicClient.readContract({ address: MINE, abi: mineAbi, functionName: 'currentMintDue' });
const hash = await walletClient.writeContract({
  address: MINE, abi: mineAbi, functionName: 'mint', args: [nonce], value: dueNow,
});
```

## 常见提交失败原因

| 报错 | 原因 | 处理 |
|------|------|------|
| `BadNonce` | 难度涨了（有人先 mint 了），旧码作废 | 重读 `currentBits()` 重新挖 |
| `NonceAlreadyUsed` | 同一地址同一 nonce 用过 | 从上次成功的 nonce 之后继续 |
| `WrongPayment` | 价格跳档了，金额不符 | 重读 `currentMintDue()` 按新价付 |
| `SoldOut` | 卖完了（总量 5000） | — |
